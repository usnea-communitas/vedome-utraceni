# Contributing to Vědomé utrácení

Thank you for helping people spend more mindfully. Contributions of every size are welcome: a bug seen on a particular phone, a better translation, a kinder tip, a workshop observation.

## Ways to help

- **Report a bug** — open an issue with the browser, device, language and the steps to reproduce. If the problem concerns your data, describe it rather than attaching a backup (backups contain your finances).
- **Improve a translation** — strings live in `fa-i18n.jsx`; the Czech text is the key, the other languages are values. Fix the text, keep the key, run `npm run compile`.
- **Add a language** — add the code to `FA_LANGS` in `fa-i18n.jsx` and a translation to every entry. A partial translation falls back to Czech, so complete it before opening a pull request.
- **Propose a tip or a reflection question** — keep the tone calm and non-judgemental; one idea per issue.
- **Share workshop feedback** — what confused participants, what helped. Open an issue tagged `workshop`.

Please open an issue before a large change so we can agree on the approach.

## Development workflow

Requirements: Node.js 20+ and npm.

```sh
npm ci
npm run compile       # after every change to a .jsx file
npx serve .           # any static server works
```

The one rule that matters most:

> **Edit the `.jsx` sources. Never edit `app.js` or `vendor/` by hand — they are generated by `npm run compile` and committed.**

Before opening a pull request:

1. `npm run compile` and commit the regenerated `app.js`.
2. Open the app in a phone-sized viewport and on a desktop; check both themes if you touched styling.
3. If you changed any text, check at least English and Czech.
4. If you changed `index.html`, `app.js`, the manifest or the service worker, bump the `CACHE` name in `sw.js`.
5. Keep privacy intact: no network calls with user data, no analytics, no accounts.

## Pull requests

- Describe what changed and why, and which devices, themes and languages you verified.
- Reference the issue you are addressing.
- One topic per pull request.

## Commit messages

Short imperative summary line, then a body if the change needs explanation. English or Czech are both fine.
